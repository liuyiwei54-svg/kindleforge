# 项目 Prompt（经 Codex 润色后落地的版本）

> 原始需求是一段口语化的中文。按用户要求，先发给 Codex 做 prompt 工程，再据此拆任务、定契约、验收。
> 下面保留润色后的**执行口径**（不是原文照抄），以及 Codex 指出的原始缺口与给 Leader 的执行建议。实际决策以 `docs/BRIEF.md` / `docs/CONTRACT.md` 为准。

## 1. 润色后的项目 Prompt（摘要版）

**项目名**：KindleForge（铸书）— 隐私优先、本地优先的电子书 / 文档转换平台。

**身份与目标**：你是 Leader，负责需求冻结、架构决策、任务拆分、接口协调、进度管理、集成与最终验收；调度 UI/UX、产品创意、前端、后端/转换引擎、测试安全、独立审核等 agent，交付一个真实可运行、可本地部署的网站，而不是设计稿。

**产品定位**：面向 Kindle 与其他阅读器的在线转换平台。宣传不得使用无法验证的「支持任何格式」，必须给出**兼容矩阵、失败原因、回退方案**。

**以 RunConvert 为竞品参照，但不复制其文案/资产/代码；差异化要落成可演示的事实**：
- **更好**：成功率、排版保真、目录质量、中文字体兼容、复杂文档处理。
- **更全面**：批量、OCR、漫画、扫描 PDF、学术论文、元数据/封面、Kindle 专项优化。
- **更绿色**：端侧优先；必须上传时用可自托管 worker；无广告追踪；默认不留存；开源可审计；绿色叙事必须对应真实实现。

**目标用户与场景**：Kindle 用户、学生/研究者、教师、作者编辑、漫画读者、档案数字化、隐私敏感个人/组织。场景包括格式转换、批量书库整理、扫描件 OCR、漫画整页、双栏论文、补封面元数据、内网/离线转换。

**功能优先级**：
- P0：上传/拖放/识别/选格式/参数/进度/取消/下载；首批输入 EPUB/MOBI/AZW·AZW3/FB2/HTML/PDF/DOCX/ODT/RTF/TXT/Markdown/图片；输出 EPUB/AZW3/MOBI/TXT/DOCX + Kindle 版 PDF；字体/边距/行距/段落/编码/封面/元数据；转换前信息与预估、转换后日志/警告/失败原因；免注册、无广告追踪、服务端临时文件自动删除；Docker 化本地部署 + README + 许可证清单。
- P1：批量与 ZIP、OCR（简中/英）、Kindle 优化（裁边、重排、去页眉页脚、灰度/对比度、图片压缩、e-ink 预设）、漫画模式、元数据与封面编辑、目录生成/修复、本地历史（只存元数据）。
- P2：双栏论文重排、脚注公式保真、URL 导入、更多 OCR 语言、转换预设、PWA、局域网部署、插件式转换器、受限 API。

**非功能要求**：真实文件类型校验；大小/解压量/页数/CPU/内存/时间限制；隔离 worker；禁止 shell 拼接；防路径穿越、宏、压缩炸弹、越权访问；绿色举措可验证；进度反馈、失败可重试不重复；移动/桌面可用，关键路径四步内；WCAG 2.1 AA 核心项；可索引的功能/格式/隐私页与结构化数据；中英双语；模块化 + 单测/集成/e2e + 最小样本集。

**技术架构建议**：前后端分离且框架可替换；浏览器优先处理文本/图片；API 负责校验、编排、限流、状态、下载授权；转换 worker 按格式路由 Calibre/Pandoc/LibreOffice/Tesseract；队列支持取消/超时/重试/幂等；本地临时存储、默认短期与自动删除；逐项核实依赖许可证，产出第三方清单与 SBOM。

**团队角色**：Leader/集成、产品与 UI/UX、前端、后端与转换、质量与安全、独立审核（不审自己写的模块）。每个任务卡必须有输入/输出/负责人/依赖/允许改动目录/接口版本/验收方法/已知风险；同一共享文件只允许一个写入者。

**里程碑**：M0 冻结范围与矩阵 → M1 P0 垂直闭环 → M2 批量/OCR/漫画/目录/封面/元数据/预览/历史 → M3 安全/性能/a11y/SEO/i18n/部署 → M4 独立审核 + 全新环境部署演练。

**最终验收**：全新环境按 README 可启动；核心转换用真实引擎；代表样本可被常见阅读器打开；取消/超时/失败/清理可验证；无阻断级安全隐私问题；测试通过；许可证与已知限制披露完整。

**主要风险**：复杂 PDF 不可保证完美重排（给预览、质量警告、保留版式/内容重排两种模式）；MOBI 退场但不移除；转换工具吃资源（隔离/配额/队列）；恶意文件（类型检测、无特权容器、资源限制）；多 agent 接口漂移（版本化契约）；宣传必须可验证。

## 2. Codex 指出的原始缺口（8 条）

1. 「任何格式」缺少可验证的兼容矩阵与实验性边界。
2. 没说明目标设备、Send to Kindle、旧 MOBI/AZW3 工作流的差异。
3. 缺少端侧 / 自托管 / 云端的优先级与降级路线。
4. 没定义文件保存期限、历史范围、日志脱敏、用户删除机制。
5. 缺少恶意文件、压缩炸弹、宏、资源耗尽、命令注入等安全约束。
6. 没有量化转换质量/成功率/性能/排版保真的验收方法。
7. 未规定第三方引擎的许可证审查、分发义务与替换策略。
8. 缺少多 agent 的目录所有权、接口冻结、集成顺序与独立审核机制。

## 3. Leader 执行建议（落地时实际采用的 8 条）

1. 先冻结 P0、格式矩阵、目录边界、API 契约，再并行开发。
2. 拆分产品/UI、前端、后端/API、转换引擎、测试安全、独立审核；工作量小时才合并。
3. 每个 agent 下发任务卡：可改目录、输入版本、交付物、可执行验收命令。
4. 前后端先确认版本化接口样例；接口变更只由 Lead 批准并同步。
5. 同一文件只有一个写者；跨模块改动走补丁/变更建议。
6. 先打通真实「上传—排队—转换—下载—清理」闭环，再扩 OCR/漫画/批量。
7. 三层门禁：执行者自检 → 独立审核 → Lead 整体验收；阻断问题最多两轮返工。
8. 最终在全新环境按 README 演练，并用固定样本集验证可打开、排版可接受、临时文件已删。
